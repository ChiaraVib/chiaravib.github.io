From Wallet Seed to Ethereum Address

Analisi approfondita della pipeline crittografica dei wallet Ethereum, dai concetti di base alle proprietà statistiche e storiche.

1. Titolo e obiettivo

Obiettivo: Esaminare ed esplorare l'intera pipeline crittografica pratica utilizzata nei wallet Ethereum per generare un indirizzo a partire da una frase mnemonica iniziale.

Pipeline analizzata: Il percorso trasforma una sequenza casuale di parole in un indirizzo crittograficamente sicuro attraverso standard di derivazione gerarchica, curve ellittiche, funzioni di hash e codifiche con checksum.

Proprietà statistiche: Vengono esaminate le caratteristiche di uniformità, imprevedibilità, diffusione (effetto valanga) e distribuzione dei bit/caratteri per comprendere il comportamento dei diversi moduli crittografici impiegati.

2. Wallet pipeline

La sequenza logica dei passaggi che compongono la generazione e derivazione di un indirizzo Ethereum:

Mnemonic → BIP-39 → Seed → BIP-32/BIP-44 → Private Key → secp256k1 → Public Key → Keccak-256 → Address → EIP-55 → Checksummed Address

1. Mnemonic → BIP-39 → Seed

Conversione di una frase mnemonica leggibile dall'uomo in un seme binario deterministico a 512 bit.

Input: 12/24 parole + Optional passphrase
Operazione: PBKDF2-HMAC-SHA512 (2048 iterazioni)
Output: 512-bit Seed
Scopo: Rendere il backup umano portabile e sicuro.

2. Seed → BIP-32 / BIP-44 → Private Key

Derivazione gerarchica deterministica (HD) per generare un intero albero di chiavi da un unico seme madre.

Input: 512-bit Seed / Albero di derivazione
Operazione: HMAC-SHA512 (Extended Key Derivation)
Output: Master Private Key / Child Private Keys
Scopo: Gestire account multipli con un unico backup (Path standard: m/44'/60'/0'/0/0).

3. Private Key → secp256k1 → Public Key

Derivazione della chiave pubblica a partire dalla chiave privata sfruttando la crittografia a curve ellittiche.

Input: 256-bit Private Key (k)
Operazione: Moltiplicazione scalare su curva ellittica ($Q = k \cdot G$)
Output: 512-bit Public Key (o compressa a 256-bit)
Scopo: Consentire la verifica delle firme digitali senza rivelare la chiave privata.

4. Public Key → Keccak-256 → Address

Compattazione e trasformazione crittografica della chiave pubblica in un identificativo di lunghezza ridotta.

Input: Chiave pubblica non compressa (senza prefisso 0x04)
Operazione: Funzione di hash crittografico Keccak-256
Output: Hash a 256 bit (vengono presi gli ultimi 20 byte / 40 caratteri hex)
Scopo: Ottenere un indirizzo di dimensioni fisse e contenute.

5. Address → EIP-55 → Checksummed Address

Applicazione di un checksum basato sul maiuscolo/minuscolo per prevenire errori di digitazione.

Input: Indirizzo esadecimale grezzo a 40 caratteri
Operazione: Keccak-256 dell'indirizzo in lowercase; i bit dell'hash determinano il case delle lettere
Output: Indirizzo misto (es. 0x5290...)
Scopo: Proteggere l'utente dall'invio di fondi verso indirizzi errati a causa di errori di battitura.

3. Concetti crittografici

Per comprendere appieno la pipeline, è fondamentale distinguere chiaramente le diverse primitive e tecniche utilizzate:

Concetto Definizione e Ruolo nella Pipeline
Key Generation Processo di creazione di un segreto casuale iniziale (chiave privata o seed) da una sorgente di entropia sicura.
Key Derivation Processo deterministico per calcolare chiavi figlie o derivate a partire da una chiave o seme master (es. BIP-32/44).
Public-Key Cryptography Sistema basato su coppie di chiavi (privata e pubblica) legate da funzioni matematiche asimmetriche unidirezionali (es. curva secp256k1).
Hashing Funzione matematica unidirezionale che mappa dati di lunghezza arbitraria in una stringa di bit a dimensione fissa (es. Keccak-256).
Checksum Meccanismo di controllo degli errori (es. EIP-55) integrato nella rappresentazione testuale dei dati per validare l'integrità.
Encoding Conversione dei dati binari in un formato testuale leggibile o standardizzato (es. Hexadecimal / Base58 / Bech32).

4. Statistical properties

Esperimento osservabile: Analizzando la distribuzione dei bit o l'effetto valanga nelle funzioni di hash (Keccak-256) e nella derivazione a curva ellittica (secp256k1), emergono proprietà statistiche chiave:

  • Effetto valanga (Avalanche Effect): Modificando anche un solo bit nella chiave privata o nel seed, l'hash risultante (Keccak-256) cambia in media circa il 50% dei suoi bit, mostrando un comportamento pseudocasuale ideale.
  • Distribuzione dei bit negli hash: I test di frequenza sui bit di output di Keccak-256 confermano un'apparente uniformità (distribuzione approssimativamente 50% zeri e 50% uni), essenziale per prevenire attacchi basati su pattern strutturati.
  • Distribuzione EIP-55: Nelle stringhe con checksum EIP-55, la combinazione di lettere maiuscole e minuscole codifica implicitamente frammenti dell'hash, distribuendo l'entropia visiva e garantendo una probabilità di rilevamento degli errori di battitura superiore al 99.9%.

5. Historical context

La linea temporale che ha portato all'evoluzione delle tecnologie impestate nei moderni wallet:

1977

RSA (Public-Key Cryptography)

Introduzione del primo pratico sistema di crittografia asimmetrica a chiave pubblica.

2001

SHA-2 / SHA-512

Standardizzazione della famiglia di funzioni crittografiche sicure da parte del NIST.

2012

BIP-32 (Hierarchical Deterministic Wallets)

Introduzione dei wallet gerarchici deterministici per derivare chiavi multiple da un unico seme.

2013

BIP-39 (Mnemonic Code)

Standard per la rappresentazione dei seed tramite sequenze di parole leggibili dall'uomo.

2014

BIP-44 (Multi-Account HD Wallets)

Definizione di uno standard strutturato per i percorsi di derivazione multi-valuta e multi-account.

2015

SHA-3 / Keccak

Standardizzazione di SHA-3 da parte del NIST sulla base della famiglia di algoritmi Keccak.

2016

EIP-55 (Ethereum Checksum Addresses)

Introduzione del meccanismo di checksum basato sul maiuscolo/minuscolo per gli indirizzi Ethereum.

6. SHA-2 vs Keccak/SHA-3

Sebbene appartengano entrambi alla famiglia delle funzioni di hash crittografiche ed condividano una parentela storica nello sviluppo delle funzioni standardizzate dal NIST, esistono differenze cruciali:

  • Architettura interna: SHA-2 si basa sulla ben nota struttura di Merkle–Damgård, mentre Keccak utilizza la costruzione a sponge function (funzione spugna), basata su permutazioni di stato e su una gestione flessibile di input e output.
  • Keccak-256 vs SHA3-256: Ethereum utilizza Keccak-256 (la proposta originaria sottomessa al concorso NIST), che differisce dal successivo standard ufficiale SHA3-256 per via del byte di padding iniziale e dei parametri di domain separation adottati dal NIST prima della finalizzazione dello standard definitivo.

7. Conclusioni

La costruzione di un indirizzo Ethereum non si affida a un singolo algoritmo onnicomprensivo, bensì a una collaborazione modulare di tecniche specializzate:

  • BIP-39 / BIP-32 / BIP-44 gestiscono in modo sicuro la memorizzazione umana e la derivazione gerarchica flessibile delle chiavi.
  • secp256k1 fornisce la solida relazione matematica asimmetrica per la coppia di chiavi e la firma digitale delle transazioni.
  • Keccak-256 assicura la riduzione unidirezionale e l'uniformità statistica necessarie per ricavare l'indirizzo pubblico senza esporre vulnerabilità.
  • EIP-55 aggiunge un livello di usabilità e sicurezza applicativa tramite il controllo degli errori di digitazione.

Questo approccio modulare permette a ciascun componente di eccellere nel proprio dominio specifico, garantendo robustezza complessiva, sicurezza e interoperabilità all'interno dell'ecosistema blockchain.
